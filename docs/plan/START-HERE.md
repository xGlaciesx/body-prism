## 0. 一句话说清这个项目

**人体棱镜 Body Prism**：同一具身体，三种读法。

- **结构之镜**：它长什么样（解剖）；
- **关系之镜**：它和谁连着、互相影响（系统）；
- **信息之镜**：它传递什么信号（概念类比）。

用户选一个器官（**11 个**：心、脑、肺、肝、肾、胃 + 脾、胆、小肠、大肠、膀胱），看到三张卡片、每条结论的证据等级和来源，还能问 AI 策展人一个问题，答案必须带引用。
**一句话卖点**：不是“又一个科普网站”，而是**把每条说法标上它有多可信**。

## 0.5 第一件事：让 AI 读一遍这个文件夹，排出一份具体计划

**如果你打算自己照着上面这句话往下做，可以跳过这一节。** 如果你想少踩坑，先花 10 分钟做这一步。

这个文件夹里有 20 多份文档，人一次读不完，但 AI 可以。把下面这段**原样**发给你的 AI（Cline、ChatGPT、Claude 都行，能读整个文件夹的那种最合适）：

```text
你是我们两个人的项目搭子。读完这些话之前，不要写任何代码、不要改任何文件。

【先读这些，按顺序】
1. START-HERE.md（开工单，一页纸）
2. MAP.md（编号规则：D 是资料，P 是计划，S 是交出去的东西，T 是任务卡）

5. 17-3d-organ-viewer.md §4.2（三维组件的最终代码）

【我们已经定死的事，不要重新讨论】

【然后输出三样东西】
A. 一张逐日计划表：D1 到 D7，每天两列（李若溪 / 张子昂），每格写：做哪张任务卡、
   具体做哪几件事、完成标志是什么（一句话，能验证）。
B. 每一步对应读哪份文档的哪一节（用 `编号 §章节` 的写法，例如 P2 · T5、D17 §4.2）。

【最后确认】
```

**AI 输出之后，你们要做的检查（两分钟）：**

1. 每天是不是**两个人都有事做**？（只有一个在动，说明它没读懂分工）
2. 每天有没有**能验证的完成标志**？（"继续开发页面"这种就不合格）
3. 有没有出现"六个器官""R3F""四个 GLB"这类旧口径？出现就说明它没读到本文的口径，让它重读 D17 §2.5–§2.6。

## 4. 每天 30 分钟的固定动作

**开工（10 分钟）**

```bash
git switch main
git pull
git switch -c feat/今天的任务
```

对 Cline 说：`读 AGENTS.md，复述今天的任务和 3 步计划，先不要改代码。`

**收工（20 分钟）**

```bash
npm run lint
npm run build
git add <改过的文件>
git commit -m "feat(范围): 一句话"
git push -u origin feat/今天的任务
```

然后开 PR → 对方 Approve → Squash and merge → 删分支。详细步骤见 14 §6。

## 6. 三分钟答辩脚本（照这个练）

**0:00–0:30 开场**

> 同一个器官，医生看到结构，系统生物学家看到关系，工程师看到信号。
> 我们做的不是把三种说法混在一起，而是给每一种说法标上**它有多可信**。

**0:30–1:30 演示（只演示一个器官）**

1. 打开 `/organ/heart`；
2. 点三镜标签：结构（四腔四瓣）、关系（自主神经）、信息（概念类比，明确标注）；
3. 指一个 **A 级**证据徽章：“这条来自解剖学教科书”；
4. 指一个 **C 级**：“这条是我们的叙事类比，不是医学结论”；
5. 打开误区区：“这条是常见误解，我们给了纠正和来源”。

**1:30–2:30 AI 策展人**

1. 问一个站内问题：“运动时心率为什么变快？”——回答带来源；
2. 问一个越界问题：“我胸痛怎么办？”——回答先建议就医，不给诊断；
3. 说一句：“模型不可用时，我们有预生成答案兜底，演示不会挂。”

**2:30–3:00 边界与收尾**

> 我们不提供诊断，不做治疗建议；中医内容标注为传统理论，信息论内容标注为概念类比。
> 所有图片只用 BodyParts3D 数据、原创图和 AIGC 辅助图，并记录生成来源。
> 下一版会做争议地图和信息负荷实验室。
