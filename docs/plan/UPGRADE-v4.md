## 4 之后每天怎么用（这就是"按计划执行"）

一天只有三个动作：**确认 → 贴提示词 → 收工同步**。

```text
开工前 2 分钟   两人在群里各发一句「D3 · 我做 P2·T5」「D3 · 我做 P2·T6」
                互相看得见今天谁动哪个文件 —— 这就是"执行前确认"，30 秒的事
                git switch main && git pull && git switch -c feat/d3-ish
开工            打开 docs/PLAN-DAILY.md，找到今天那格，
                把对应那段代码块整块复制给 Cline（不用自己想怎么问）
收工前 10 分钟  跑那格的"收工命令"；通过就 commit → push → PR
收工后 5 分钟   把 §4.2 的「同步提示词」贴给 Cline，让它按今天的实际情况更新计划
明天            拉最新 main，重复上面
卡住            先看那格的"卡住先看"；30 分钟没动就按 START-HERE §7 找人
```

### 4.1 三条硬规矩

1. **今天和以前不改，只改明天及以后。** `PLAN-DAILY.md` 是账本：D1 做完就锁死（状态改成"✅ 已完成"，补一句实际做到哪），AI 再更新也不能回头改它。这样出了问题能看出是哪天开始偏的。
2. **每天只做当天那格。** 想提前做明天的事，先问对方，避免两个人改同一个文件。
3. **每天一个 PR。** D7 晚上要能数出至少 6 个已合并的 PR，这是比赛要看的东西。
4. **分支不过夜。** 每天开的 `feat/d?-*` 当天合回 `main`。过夜的分支，第二天早上第一件事是先合掉它，再开新的。**绝不能攒到 D7 一次性合并**——那时已经没有时间解冲突了（`RUNBOOK.md` §4.6 有完整的所有权表和冲突处理步骤）。

### 4.2 收工同步提示词（每天收工后贴一次）

```text
【同步计划】读 docs/PLAN-DAILY.md，按今天的实际进度更新它。

今天的情况：（自己填一行。例：T3 做完了；T4 只写完 2 个函数，测试还没写）

更新规则：
1. 今天那格：状态改成「✅ 已完成」或「⚠️ 部分完成」，后面补一句实际做到哪
2. 没做完的：整条顺延到明天的同一列。不要删、不要合并、不要偷偷降级成"可选"
3. 明天及以后：按剩余天数重排。时间不够时按这个顺序砍：T11 别名搜索 → T14 三维入口
   → T13 首屏叙事 → 缓存优化。每砍一项，必须在「更新记录」里写一行"砍掉 X，理由 Y"
4. 守恒检查：T0–T14 每一张卡，要么出现在某一天，要么被显式标记"已砍（理由）"。
   不许有卡片凭空消失。检查完把结论写在更新记录里
5. 重写"明天"那两格的提示词块，依据今天的真实产出
   （比如接口签名已经定了，就把真的签名写进提示词，别留占位符）
6. 顶部状态行、更新记录表同步更新
7. 不要动 <!-- 人工备注开始 --> 到 <!-- 人工备注结束 --> 之间的内容
8. 不要改 docs/plan/ 里的方案包原件

做完用 5 行以内说：改了哪几处、明天两个人各做什么。
```

**为什么值得每天花这 5 分钟**：孩子不熟、会卡、会落后。一份排死的计划，第 3 天落后就整份作废，人就会放弃看它；每天重排一次，落后自动顺延、时间不够自动砍，计划永远和现实对得上，孩子随时知道"今天只做这一件"。

> **计划拿到之后怎么用，看 [`RUNBOOK.md`](RUNBOOK.md)（P8）。**
> 那里有：前 90 分钟的逐条动作、跟 Cline 说话的五个句式（含四句绝不能说的话）、七天每晚必须看到的画面、卡住时按现象查的 20 条、以及按天数算的止损线。

## 6 这一步最容易翻车的几个地方

| 现象 | 原因 | 怎么查 |
|---|---|---|
| 首页报 `Cannot find module 'three'` 或 `@react-three/...` | 依赖卸了，但旧组件还 import 着 | `grep -r "three\|@react-three" src/`，把旧三维组件整个删掉，不要"改一改继续用" |
| 模型不出现，但控制台没有红色报错 | 漏了 meshopt 解码器，或版本不对（装了 1.x 的 ESM 版） | Network 里看 `meshopt_decoder.js` 是不是 200；文件末尾应有 `self.MeshoptDecoder = MeshoptDecoder`（D17 §2.6.3） |
| 页面报 `The node to be removed is not a child of this node` | 条件渲染了 `<model-viewer>` 的子元素（热点） | 热点列表必须是模块级常量 `.map()`，不能包在 `{loading && ...}` 里（D17 §4.2） |
| 计划越更越短，任务悄悄没了 | AI 每天重写时把没做完的删了，或者把"必须做"降成"可选" | 收工时数一遍：T0–T14 是不是 15 张都还在（或明确标了"已砍+理由"）。§4.2 第 4 条就是防这个的，别删掉那句 |
| AI 改了「人工备注」区块，或回头改了已完成的天 | 提示词少写了一条约束 | §4.2 第 1、7 条；发现后用 `git diff docs/PLAN-DAILY.md` 看出来并 `git checkout -- docs/PLAN-DAILY.md` 重贴一次 |
