# 文档地图：编号、文件名、章节号怎么对应

> 文档编号 **M0** · 找不到东西时先看这一页。三十秒能查完。

---

## 0 先说清楚以前乱在哪

之前文档里同时跑着三套坐标，互相不通：

1. **文件名前缀** `00`–`16`：看起来像"完整序列"，其实只是写入的先后。
2. **HTML 页眉上的"文档 04"**：和文件名一致，但和正文里的"第 4 节"长得几乎一样。
3. **正文里的"见第 3 节"**：说的是**这一篇自己的**第 3 节，但读者分不清是"文档 03"还是"第 3 节"。

于是出现两种误读：看到"见 §6"以为是文档 06；看到"文档 04"以为是第四章。**这就是查找困难的原因。**

---

## 1 现在的规则（只有一条）

> **所有交叉引用都写成 `编号 §章节`。装不下就分开写。**

| 写法 | 意思 |
|---|---|
| `D07 §8` | 第 D07 号文档的第 8 节 |
| `D07 §8.2` | 第 D07 号文档第 8 节的第 2 小点 |
| `P2 · T5` | 参赛/实施类文档 P2 里的任务卡 T5（任务卡没有章节号，用卡号定位） |
| `S1 §3.3` | 提交材料 S1（技术文档）的第 3.3 节 |
| `D17` | 整篇 |

**反过来也成立**：正文里只写"见第 5 节"，一律视为错误，要么补编号，要么改成"见本文第 5 节"。

**编号不表示阅读顺序。** 编号是门牌号，先看哪份由 P5 开工单决定。

## 2 三套编号各管什么

| 前缀 | 管什么 | 数量 | 会不会变 |
|---|---|---|---|
| **D** | 参考资料：环境、Git、Web、AI、素材、打法等 | D00–D17 | 只增不改号 |
| **P** | 方案与说明：给孩子看的计划、给老师看的说明、给家长的说明 | P0–P10 | 只增不改号 |
| **S** | 要交出去的材料 | S1–S5 | 只增不改号 |
| **T** | 任务卡，只存在于 P2 里 | T0–T14 | 增卡往后排，不重排 |
| **M** | 地图本身 | M0 | — |

## 4 章节号怎么读

每一篇自己的章节都从 **1** 开始编，和文档编号**没有**关系：

```
D07 §3   → 打开 07-page-design.md，找 "## 3." 开头的那一节
P2 §6.3  → 打开 PLAN-V4-implementation.md，找 "### 6.3 只有三天怎么办"
```

两点容易搞混：

- Markdown 里的 `## 3.` 会渲染成"3."，`### 6.3` 渲染成"6.3"，编号即标题前缀，肉眼可对。
- 任务卡（T0–T14）**没有**章节号，它们平铺在 P2 §5 里。引用卡片时只写卡号，不写章节：写 `P2 · T8`，不写 `P2 §5 T8`。

## 5 一句话记忆

> **D 是资料，P 是计划，S 是交出去的东西，T 是今天要干的活。**
> 引用一律 `编号 §章节`，不带编号的"第 X 节"视为写错。
