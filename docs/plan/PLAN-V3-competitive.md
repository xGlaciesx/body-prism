# 参赛方案 v3：从「器官百科」到「可核对的身体影响链」

> 依据：老师的两条建议 + 仓库 `main` 实际进度 + 大赛评分材料要求。
> 结论先行：**现在这个版本是"一个做得很干净的三镜百科"，还不是"一个有主张的作品"。**
> 差的那一步，老师已经指出来了——把它补上，项目才立得住。

---

## 0 一句话定位（换掉原来的）

**原来是**：同一个器官，三种读法。

**建议改成**：

> 通用大模型能告诉你"是什么"，但不会告诉你"凭什么"。
> 人体棱镜把每条身体结论的**推理链**摊开：每一步都能点开，都标着可信度。

口号（答辩时反复说的那一句）：

> **看得见的推理链，查得回的证据。**

"三镜"从产品主张降级为**叙述框架**，不再是核心卖点。理由见本文 §1。

## 1 老师两条建议为什么必须一起做

老师的第 1 条是**叙事**（讲清楚为什么这件事值得做），第 2 条是**产品**（做一个能看见的东西）。单做任何一条都不够：

| 只做 | 后果 |
|---|---|
| 只改背景故事 | 答辩被问"那你和通用大模型到底差在哪"，还是答不上 |
| 只加关系图 | 变成"又一个知识图谱大屏"，评审见过太多，且和 AI 无关 |
| **两条一起** | 图谱是"链"的数据基础，AI 是"链"的入口，证据分级是"链"的刻度——**三者互为证据，才是壁垒** |

所以新版的骨架是三层，缺一层就散：

```text
数据层  结构化影响图谱（节点 = 器官/功能/表现，边 = 影响关系，每条边带证据等级与来源）
   ↓
推理层  AI 只能在图上走（图谱约束的 RAG），输出路径逐边校验
   ↓
交互层  用户能沿着链子点、能追着链子问
```

## 2 背景叙事（直接用于技术文档 §1、视频前 40 秒、答辩开场）

三句话，背下来：

1. **人们查身体的方式变了。** 过去是"搜症状"，现在是直接把不舒服丢给 AI 问一句。
2. **但通用大模型给的是结论，不是推理。** 它不会告诉你这句话来自哪本教科书、哪些是共识、哪些只是假说；你说"胸痛"，它也可能继续陪你分析。
3. **我们做的不是另一个问答机器人，而是给 AI 装上一条可核对的推理链。** 结论来自结构化图谱，每条关系有证据等级和出处；**链断了，我们就明说"这里没有依据"**。

补一句把"专业结合"说出来（老师第一条点到的）：

> 我们两个人一个学电子信息工程、一个学临床医学。这个项目真正做的事，是把**医学的证据分级习惯**翻译成**工程可校验的数据结构**——这是单专业做不出来的东西。

这句话在答辩里非常值钱，它把"两个大一学生"从劣势变成理由。

## 3 核心新功能：影响链（Impact Chain）

### 3.1 用户看到的

选一个器官，看到三件事：

- **它受谁影响**（上游）
- **它影响谁**（下游）
- **它出问题时，身体可能出现什么表现**（表现，不是症状）

每条箭头都能点开：一句话机制、证据等级、来源、限定条件。

一句话：**从"心脏有四个腔"变成"肾不好为什么会气短"。**

### 3.2 为什么这个功能能加分（而不是"又一个关系图"）

1. 它回答的是用户真正会问的问题（"熬夜为什么心慌"），不是教科书目录；
2. 器官之间的关系强度差异极大，**天然承载 A/B/C 证据分级**——正好把项目的核心主张演示出来；
3. 它给 AI 提供了可执行的推理路径，而不是一段自由文本；
4. 它带来一个**评委一眼就懂的对比演示**（见本文 §7）。

### 3.3 页面形态（工程量可控）

入口 `/chain`。**用 SVG，不用 3D**——3D 是时间黑洞，且手机端体验差。

```text
        ┌──────── 表现层（外圈）────────┐
        │  气短  水肿  乏力  心悸  黄疸  │
        └───────────────┬──────────────┘
        ┌──────── 功能层（中间）────────┐
        │  血压  血容量  氧合  凝血  血糖 │
        └───────────────┬──────────────┘
        ┌──────── 器官层（内圈）────────┐
        │  心   脑   肺   肝   肾   胃   │
        └───────────────────────────────┘
```

交互（按优先级，做不完就从下往上砍）：

1. **点器官** → 高亮一阶出入边，右侧列出"影响谁 / 被谁影响 / 可能表现"
2. **点箭头** → 卡片：机制 + 证据等级徽章 + 来源 + `caveat`
3. **走一条链**（加分项）→ 选起点终点，最短路径逐段点亮
4. **红旗表现**（胸痛、呼吸困难、意识丧失）→ 红色节点，点击弹"立即就医"

移动端：图退化成"分组列表 + 迷你链"，绝不横向滚动。

### 3.4 三个必演示路径（写进视频脚本和答辩）

| # | 路径 | 讲什么 |
|---|---|---|
| 1 | 肾 → 血压 → 心脏 → 气短/水肿 | 跨系统传导，4 跳，最能体现"链" |
| 2 | 肝 → 凝血因子 → 出血倾向 | 2 跳，回答"为什么肝硬化会出血" |
| 3 | 脑 → 自主神经 → 心率 | 情绪为什么影响心跳，同时是"信息之镜"的落点 |

### 3.5 伦理措辞（这是加分项，不是负担）

评审对医疗类作品最敏感的就是"会不会误导人自我诊断"。我们把它做成**产品结构**，而不是文末免责：

- 表现区标题不写"症状"，写「**可能相关的表现（科普参考，不用于自我判断）**」；
- 每条表现固定附一句："这些表现也可能来自其他原因，不能据此判断某个器官有问题。"
- 边分三类，不混用因果：`affects`（影响）/ `modulates`（调节）/ `manifests`（表现）
- 每条边强制填 `caveat`：至少写"关联不等于因果"或"存在个体差异"

答辩时可以主动说：

> 我们刻意没有做症状自查。因为一张"输入症状 → 输出疾病"的表，本质上是在做诊断，而我们没有资格做。

这句话会给评委很好的印象。

## 4 AI 升级：从"带引用的回答"到"可核对的链"

### 4.1 现状（重要）

仓库 `main` 里 **`src/app/api` 目录不存在**——AI 策展人只有兜底答案，没有真实接口。
这是当前最大的缺口：技术文档写了 AI 章节，代码里没有对应实现，评委一对照就露。

### 4.2 新的调用流程（写进技术文档 §4）

```text
用户提问
  ↓
① 红旗前置拦截（胸痛/呼吸困难/晕厥/大出血）→ 直接就医提示，不进模型
  ↓
② 定位器官（关键词或模型轻量判断）
  ↓
③ 取子图：目标器官 + 一阶邻居 + 相关表现（约 20–40 条边）
  ↓
④ 调模型，强制 JSON：{ answer, path:[{from,to}], sourceIds:[] }
  ↓
⑤ 逐边校验：path 里每条边必须在子图中；sourceIds 必须存在
     ├─ 通过 → 渲染「正文 + 链式卡片」
     └─ 不通过 → 丢弃该段；整条失败 → 回退预生成答案
```

术语用准确：这叫 **Graph-constrained RAG（图谱约束的检索增强）**。评审喜欢有准确术语、且能解释清楚的方案。

### 4.3 和通用大模型的区别（一句话）

> 通用模型的引用是"生成的"，我们的引用是"校验过的"——**模型编一个不存在的来源，程序会把它删掉。**

## 7 演示设计：一个让评委记住的 60 秒

这是整份方案里回报最高的一段，务必照做：

> **并排两个窗口，问同一个问题："肾不好为什么会气短？"**
>
> 左边：通用大模型，给一段流畅的解释，没有来源，也没法核对。
>
> 右边：人体棱镜，给出**一条链**——肾 → 血容量/血压 → 心脏负荷 → 肺淤血 → 气短。
> 每一段都能点开，写着机制、证据等级、教科书出处。
>
> 然后补一句：**"左边那段话可能是对的，但你没有办法知道它对不对。这就是我们要解决的问题。"**

这一段同时回答了老师的两条建议：背景（为什么做）+ 功能（看见了什么）。

## 8 创新点重写（技术文档 §8 直接替换）

### 8.1 技术创新

1. **边级证据分级的知识图谱**：证据等级不是文章级标签，而是**每一条关系**的必填字段；构建期校验 `sourceIds` 是否存在，**悬空即构建失败**。
2. **图谱约束的 RAG**：模型只能在给定子图内组织答案，输出路径逐边回溯校验；模型无法"走出图外"编造关系。
3. **引用存在性校验**：回答中的每个 `sourceId` 必须命中真实数据，否则丢弃；引用为空整条回退——从工程上阻止编造引用。
4. **链式三级降级**：模型不可用 → 预生成链；图渲染不可用 → 列表视图；JS 不可用 → 服务端渲染文本仍可读。
5. **红旗前置拦截**：安全逻辑在模型之前，急症词不进入推理。

### 8.2 应用创新

1. **从"器官百科"到"影响链"**：回答"它坏了，身体会怎样"，而不是"它长什么样"。
2. **把"关联≠因果"做成界面约束**：表现区固定提示 + 边级 `caveat`，而不是文末免责。
3. **同一器官三种读法并置**：结构、关系、信息同屏对照。
4. **面向信息素养**：`/method` 公开分级规则，读者学会"怎么判断一条健康说法"。
5. **跨专业协作的产品化**：医学生定证据、工科生定校验，两套习惯被写进同一个数据结构。

### 8.3 对比表（加两行）

| 维度 | 常见科普站 | 通用 AI 问答 | 人体棱镜 |
|---|---|---|---|
| 内容组织 | 按文章 | 按对话 | 器官 × 三镜 × **影响链** |
| 能否回答"为什么" | 弱 | 能，但不可核对 | 能，且**逐段可核对** |
| 引用 | 文末参考 | 常缺失或编造 | 程序校验存在性 |
| 因果表述 | 混写 | 自由发挥 | `affects/modulates/manifests` 三类分离 |
| 边界 | 依赖编辑 | 依赖提示词 | 提示词 + 红旗拦截 + 人工审核 |

## 11 参考实现：`aaron603/body-prism` 值得抄什么、不该抄什么

这个库是同名同命题的另一种实现：**Vue 3 + Vite + Three.js**，一块 3D 人体，11 个系统图层、68 个结构、三语术语、剖面、搜索、出题、PWA。技术上完成度很高，但它**没有任何 AI**——所以它是"人体介绍"的优秀样本，不是我们要走的方向。

### 11.1 值得直接借鉴的四点

| 借鉴点 | 他们怎么做的 | 我们怎么用 |
|---|---|---|
| **内容模型带"关系字段"** | 每个结构有 `relations: { origin, insertion, innervation, bloodSupply }`，值是可以点进去跳转的 id | 我们的 `ImpactEdge` 已经有 `mechanism`，补一个 `via`（经由什么：神经/激素/血流/压力），链就有了"怎么过去的"细节 |
| **内容与图形解耦** | `structure_map.json` 把内容 id 映射到模型节点；没模型的用 `placeholderBody.ts` 里的简化几何 | 链节点与 SVG 图形解耦：先出内容和交互，图形后补；缺图形的节点用圆点占位，不阻塞 |
| **视图逻辑写成纯函数并单测** | `visibility.ts` 只有 30 行：`isEntryVisible()` / `entryOpacity()` 纯函数，不碰 WebGL，可直接跑单测 | 把"当前选中器官 → 应高亮哪些边"写成 `getChainHighlight(state)` 纯函数，逻辑可测，不埋在组件里 |
| **搜索考虑中文输入习惯** | Fuse.js + pinyin-pro，索引中文/英文/拉丁/同义词/全拼/首字母，中英权重 3、拉丁 2、拼音 1.5/1 | 用户搜的是"心慌""xinhuang"，不是"心悸"。链页必须有这个 |

### 11.2 可以考虑加的一个功能：小测

他们从结构化内容自动出题（点选 / 识图 / 术语互译），错题本存本地。成本极低、观感很好，而且和"科普"定位一致。

我们能做的最小版本：从 11 个器官的 claims 自动生成"这条说法是 A 还是 C 级"的判断题，5 题一组，答完显示"你最容易相信哪一级的证据"。**这比再加一个器官页有记忆点。**

### 11.3 不该抄的两点

- **3D 资产管线**（230 MB FBX → glb、减面、meshopt）：投入产出比不适合我们一周的排期，而且我们的主张是"链"，不是"模型精度"；
- **换技术栈重写**：Vue 还是 React 不影响评分，重写的代价我们付不起。
