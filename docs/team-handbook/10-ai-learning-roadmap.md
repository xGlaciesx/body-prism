# AI 学习路线：从“会用”到“懂原理”，再到“知道怎么学”

> 读者：大一新生，非计算机专业也能读。
> 目标：分清 AI 的应用、技术、原理三层；知道 2026 年产业大概长什么样；有一个可执行的四年学习计划；拿到一份靠谱的资源清单。
> 说明：AI 变化极快，本文的“产业快照”截至 **2026 年 10 月**，具体型号几个月就会变。**学能力维度，不要背型号。**

---

## 0. 先分清三层，避免一上来被公式劝退

很多人学 AI 失败，不是因为笨，而是因为把三层混在一起：

```text
┌──────────────────────────────────────────────┐
│ 应用层：会用                                    │
│ Chat、提示词、Cline 写代码、AIGC 出图、RAG 问答  │
├──────────────────────────────────────────────┤
│ 技术层：懂系统                                  │
│ API、token、上下文、embedding、向量库、Agent     │
├──────────────────────────────────────────────┤
│ 原理层：懂为什么                                │
│ 线代、概率、优化、神经网络、Transformer、扩散模型 │
└──────────────────────────────────────────────┘
```

对你们这个比赛：

| 层级 | 需要到什么程度 | 投入比例 |
|---|---|---|
| 应用层 | 熟练：能稳定用 AI 写代码、做图、查资料 | 50% |
| 技术层 | 能讲清：token、RAG、流式、模型路由、成本 | 35% |
| 原理层 | 能讲清概念：注意力、预训练、幻觉从哪来 | 15% |

**不要从《深度学习》花书第一页开始啃。** 那是大三/研究生阶段的路线。大一先做出东西，再回头补原理。

## 1. 概念地图

### 1.1 从大到小

```text
AI（人工智能）
└─ ML（机器学习）
   └─ DL（深度学习）
      └─ LLM（大语言模型）
         └─ GenAI（生成式 AI）
            └─ AIGC（AI 生成内容：图、文、音、视频）
```

| 词 | 一句话 |
|---|---|
| AI | 让机器表现出“智能”的总称 |
| ML | 不写死规则，让机器从数据里学规律 |
| DL | 用多层神经网络做 ML |
| LLM | 用海量文本训练的大语言模型 |
| GenAI | 能生成新内容的 AI |
| AIGC | GenAI 在内容生产上的应用 |
| AGI | 通用人工智能，目前是目标而非事实 |

### 1.2 学习方式

| 类型 | 怎么学 | 例子 |
|---|---|---|
| 监督学习 | 有标准答案 | 给图片标“心脏/肝脏” |
| 无监督学习 | 没有标准答案，找结构 | 用户分群、异常检测 |
| 自监督学习 | 从数据本身造答案 | 预测下一个词，GPT 就是这样 |
| 强化学习 | 通过奖励试错 | AlphaGo、RLHF |

### 1.3 大模型常用词

| 词 | 解释 | 对你们的意义 |
|---|---|---|
| token | 模型处理文本的最小单位，约等于半个到一个词 | 计费按 token |
| 参数 | 模型里可学习的数字 | 不是越多越好 |
| 上下文窗口 | 一次能“看见”的 token 数 | 决定能塞多少资料 |
| 温度 temperature | 输出的随机程度 | 医学内容调低，创意文案调高 |
| embedding | 把文本变成向量，用于相似度检索 | RAG 的基础 |
| RAG | 先检索资料，再让模型基于资料回答 | 减少幻觉、可引用来源 |
| 微调 fine-tuning | 用自有数据继续训练 | 比赛阶段通常不需要 |
| LoRA | 低成本微调方法 | 需要显卡，暂不涉及 |
| Agent | 模型能调用工具、分步完成任务 | Cline 就是一个编码 Agent |
| 多模态 | 同时处理文字、图片、音频、视频 | 器官图识别、语音导览 |
| 幻觉 hallucination | 模型编造看似合理但不真实的内容 | 医学项目必须引用来源 |
| 对齐 alignment | 让模型行为符合人类意图和价值观 | RLHF 是手段之一 |

### 2.1 两次寒冬的教训

1. **算力、数据、算法，缺一不可。** 1950–80 年代的想法并不都错，是条件不够。
2. **期望越高，回落越狠。** 今天也有人把 AI 说成万能，保持清醒。
3. **真正的突破往往来自“基础设施 + 规模 + 简单方法”**，不是某个神奇公式。

## 3. 原理主线：不要求推公式，要求能讲清

### 3.1 机器学习 = 找一个函数

```text
数据 → 模型（带参数的函数）→ 预测 → 和答案比较 → 损失
                                        ↓
                                  调整参数，让损失变小
```

- **损失函数**：衡量预测和答案差多少。
- **梯度下降**：沿着让损失变小的方向，一点点调参数。
- **过拟合**：在训练集上很好，在新数据上很差。
- **训练集 / 验证集 / 测试集**：不能拿考试题当练习册。

### 3.2 神经网络与反向传播

- 一个神经元：输入 × 权重 + 偏置 → 激活函数 → 输出。
- 多层堆叠：能拟合更复杂的函数。
- 反向传播：从损失往回算每个参数该往哪调。
- 激活函数：ReLU、GELU，让网络有非线性。

**直觉：** 神经网络不是“模拟大脑”，而是一个**可微分的函数近似器**。大脑是灵感来源，不是实现图纸。

### 3.3 从词到向量

- 文本先切成 **token**；
- 每个 token 查表变成一个 **向量**；
- 语义相近的词，向量距离近；
- 这就是为什么可以用 embedding 做检索、聚类、推荐。

### 3.4 Transformer 与注意力

2017 年的 Transformer 解决了一个关键问题：**让序列里的每个位置都能直接“看”其他位置，并且能并行计算。**

- **Query（我在找什么）**
- **Key（我有什么）**
- **Value（我能提供什么）**

注意力就是：用 Q 和每个 K 算相似度，得到权重，再对 V 加权求和。

不需要背公式，但要能回答：

- 为什么 Transformer 比 RNN 更容易并行？
- 为什么上下文越长，成本越高？
- 位置编码是干什么的？

### 3.5 大模型怎么练出来

```text
1. 预训练：在海量文本上预测下一个 token
2. 指令微调：用“问题-答案”教它听指令
3. 偏好对齐：用人类偏好（RLHF / DPO）让它更有用、更安全
4. 推理增强：让它先写草稿、再检查（test-time compute）
```

- **Scaling law**：参数、数据、算力一起增加，能力可预测地提升（但有边界）。
- **推理模型**：不是“更大”，而是“回答前想更久”，用更多推理 token 换准确率。

### 3.6 图像生成：从 GAN 到扩散模型

- **GAN**：生成器和判别器互相对抗。
- **扩散模型**：先把图逐步加噪声，再学怎么一步步去噪；从纯噪声生成图。
- **文生图**：用文本 embedding 引导去噪过程。

这解释了为什么提示词里“风格、构图、光线、材质”越具体，结果越可控。

### 3.7 Agent：从“回答”到“行动”

```text
观察（读文件/看报错）→ 思考（计划）→ 行动（改代码/跑命令）→ 再观察
```

Agent 的关键不是模型更大，而是：

- 能调用工具；
- 有记忆/上下文；
- 能分解任务；
- 有人类检查点。

Cline 就是“编码 Agent”：它能读你的仓库、改文件、跑终端，但**必须由你看 diff、做决定**。

### 3.8 幻觉从哪来

- 模型是**概率生成**，不是数据库查询；
- 训练数据里没有的内容，它会“编一个看起来合理的”；
- 上下文窗口有限，长文档会丢细节；
- 基准测试会饱和，榜单高不等于在你的任务上可靠。

**对策：**

1. 关键结论必须给来源；
2. 医学内容人工审核；
3. RAG 只索引已发布内容；
4. 让模型说“不知道”；
5. 用结构化输出 + 校验。

### 3.9 一页公式（看懂符号即可）

```text
信息熵：H(X) = -Σ p(x) log p(x)
交叉熵：H(p, q) = -Σ p(x) log q(x)
Softmax：把一组分数变成概率
注意力：Attention(Q, K, V) = softmax(QKᵀ / √d) V
```

你们不需要手推，但答辩时能解释“softmax 是把分数变概率”“注意力是加权求和”，会显得真懂。

### 4.3 2026 年几个值得知道的事实

来自斯坦福 **AI Index 2026**（2026 年 4 月发布）：

- 生成式 AI 在三年内触达全球约 **53%** 的人口，比 PC 和互联网都快；
- 中美顶级模型的差距缩小到约 **2.7%**；
- 编程基准 SWE-bench 的顶尖成绩一年内从约 60% 接近人类基线；
- 同一批模型在“赢数学奥赛”和“看模拟时钟”之间表现差异巨大，这叫 **锯齿状能力边界**；
- 26 个头部模型的幻觉率在 **22%–94%** 之间，差别很大；
- 2025 年全球企业 AI 投资约 **5810 亿美元**。

**结论：**

1. 不要问“哪个模型最强”，要问“这个任务上，哪个模型够用且便宜”。
2. 榜单会饱和，真实任务上的评测更重要。
3. 成本和稳定性，已经是和“能力”同等重要的竞争维度。

### 4.4 选模型的实用原则

| 场景 | 建议 |
|---|---|
| 写代码、改仓库 | 选编程能力强的；Cline 里可切换 |
| 医学内容润色 | 中文好、可控、低温度；必须人工审核 |
| 长文档总结 | 上下文窗口大、引用能力强 |
| 批量分类/抽取 | 便宜的小模型 + 结构化输出 |
| 图片生成 | 看风格一致性、授权、是否可商用 |
| 演示 | 提前缓存结果，避免现场网络/限流 |

**不要站队。** 按任务、价格、中文能力、隐私、稳定性选。

## 5. 这个项目里，AI 的四种用法

| 用法 | 工具 | 做什么 | 风险 | 人工检查 |
|---|---|---|---|---|
| Chat | ChatGPT / Claude / DeepSeek / 豆包 | 查概念、解释报错、润色文案 | 幻觉、过时 | 查原始来源 |
| Code | Cline + DeepSeek | 读仓库、改代码、跑命令 | 改错文件、引入依赖 | 看 diff、跑 lint/build |
| AIGC | Midjourney / Stable Diffusion / 即梦 / 可灵 | 器官插画、背景、图标 | 版权、风格不一致、解剖错误 | 医学审核、来源记录 |
| RAG / Agent | Vercel AI SDK + Supabase | 基于已发布内容回答、带引用 | 检索错、引用假 | 评测集、引用核验 |

### 5.1 比赛里最容易加分的 AI 用法

1. **RAG 带引用**：回答里每个结论都能点回来源；
2. **证据等级**：A/B/C/D 明确标注；
3. **不确定性表达**：不知道就说不知道；
4. **成本控制**：缓存、路由、Mock，现场不炸；
5. **可解释**：你们能讲清每个 AI 调用在哪、输入输出是什么。

### 5.2 不建议在比赛里做的

- 从头训练模型；
- 微调一个医学大模型；
- 做通用聊天机器人；
- 让 AI 直接给诊断/剂量；
- 把 API Key 放前端。

## 6. 大学四年怎么学

### 6.1 两条路线

```text
工程路线：能做产品、能部署、能协作
研究路线：能读论文、能复现、能做实验
```

大一不需要二选一。先走工程路线，做出作品；大二再决定要不要偏研究。

### 6.2 分年级计划

| 阶段 | 数学 | 编程 | AI 课程 | 实践 | 产出 |
|---|---|---|---|---|---|
| 大一上 | 微积分、线代 | Python 基础 | 3Blue1Brown 神经网络 | 这个比赛 | 一个完整 Web 作品 |
| 大一下 | 线代、概率 | 数据结构 | 吴恩达 ML 专项 | Kaggle 入门 | 2–3 个 notebook |
| 大二上 | 概率统计 | 算法、数据库 | 李宏毅 ML | 开源贡献 | 第一个 PR |
| 大二下 | 最优化 | 后端/前端 | CS231n 或 CS224n | 校级/省级竞赛 | 一个 AI 应用 |
| 大三上 | 随机过程/信息论 | 工程化 | 6.S191 / 论文阅读 | 实验室/实习 | 复现一篇论文 |
| 大三下 | 按方向 | 按方向 | 方向专精 | 实习 | 作品集 |
| 大四 | 按需 | 按需 | 按需 | 毕设/求职/申请 | 毕业论文 |

### 6.3 数学最小集

不要一上来学完整本数学分析。先掌握：

- **线性代数**：向量、矩阵乘法、秩、特征值、内积；
- **概率**：条件概率、贝叶斯、期望、方差、常见分布；
- **微积分**：导数、偏导、链式法则、梯度；
- **优化**：梯度下降、学习率、凸/非凸的直觉。

推荐资源：

- 3Blue1Brown《线性代数的本质》《微积分的本质》；
- Khan Academy 概率与统计；
- 吴恩达课程里的数学复习部分。

### 6.4 每周 4 小时的学习模板

```text
周一 60 分钟：看一节课程/读一篇文档
周三 60 分钟：动手复现，写代码
周五 60 分钟：做一个小项目/改比赛代码
周日 60 分钟：写笔记 + 复习 + 计划下周
```

**关键不是强度，是不断线。** 每周 4 小时，坚持一年，比暑假突击两周有用。

### 6.5 作品集怎么攒

- 3 个能跑的项目（这个比赛算 1 个）；
- 1 篇技术笔记（比如“我们如何把 AI 成本压到 300 元以内”）；
- 1 个开源 PR（文档、测试、小 bug 都算）；
- 1 个能讲 5 分钟的 demo 视频。

## 8. 信息辨别与学术诚信

### 8.1 三个习惯

1. **看到“研究表明”，先找原始论文。** 新闻标题经常夸大。
2. **看到榜单，先看评测集。** 榜单可以过拟合。
3. **看到“AI 将取代所有人”，先看谁在卖课。** 焦虑是流量生意。

### 8.2 用 AI 做作业/比赛的边界

- 可以用 AI 查概念、改语法、生成初稿、解释代码；
- 不能把 AI 生成的医学结论直接当事实；
- 不能把别人的代码/图片说成自己原创；
- 比赛要求的 AIGC 声明、引用、授权，必须如实写；
- 答辩时，**你必须能解释每一行代码和每一条医学结论**。

### 8.3 给 AI 内容打标签

在项目里统一用：

```text
[研究] 有论文/指南支持
[类比] 为了理解做的比喻，不是结论
[传统理论] 中医/传统哲学表述，非现代医学共识
[AIGC] AI 生成或辅助生成，附工具与提示词
```

## 9. 一页学习卡

```text
三层：应用（会用）→ 技术（懂系统）→ 原理（懂为什么）
先做：应用层熟练，技术层能讲清，原理层不逃避
历史：三次浪潮、两次寒冬；算力+数据+算法+期望
原理：函数拟合 → 神经网络 → 注意力 → 预训练/对齐 → 推理
产业：不站队，按任务/价格/中文/稳定性选
项目：Chat 查、Code 写、AIGC 画、RAG 答；全部要人工检查
四年：数学+编程+课程+项目+论文，每周 4 小时不断线
底线：引用来源、标注 AIGC、医学内容人工审核、密钥不进前端
```

> **AI 不是替代你思考，而是把“查资料、写初稿、改语法”的时间省下来，让你把时间花在判断和创造上。**
