# 开工单：7 天做出可演示的「人体棱镜」

> 给两个人看的一页纸。看完这一页，就知道今天做什么、做到什么算完。
> 详细操作在 [00 主线手册](00-start-here.html)，内容素材在 `content-pack/`，页面设计看 [07](07-page-design.html)，写代码顺序看 [16](16-mvp-implementation.html)。

---

## 0. 一句话说清这个项目

**人体棱镜 Body Prism**：同一具身体，三种读法。

- **结构之镜**：它长什么样（解剖）；
- **关系之镜**：它和谁连着、互相影响（系统）；
- **信息之镜**：它传递什么信号（概念类比）。

用户选一个器官（11 个：心、脑、肺、肝、肾、胃、脾、胆、小肠、大肠、膀胱），看到三张卡片、每条结论的证据等级和来源，还能问 AI 策展人一个问题，答案必须带引用。
**一句话卖点**：不是“又一个科普网站”，而是**把每条说法标上它有多可信**。

## 2. 两个人怎么分工

| | 女孩（信息工程） | 男孩（临床医学） |
|---|---|---|
| **主责** | 工程：环境、Next.js、页面、组件、部署 | 内容：医学审核、证据等级、来源、答辩口径 |
| **每天固定** | 早 10 分钟：`git pull` + 开分支；晚 10 分钟：lint/build + PR | 早 10 分钟：看 PR；晚 10 分钟：审当天新增的医学表述 |
| **不可替代** | 只有她能改代码结构、跑构建 | 只有他能判断“这句话能不能这么说” |
| **交付物** | 能跑的项目 + 每周可演示版本 | 六个器官的内容审核记录 + 3 分钟答辩稿 |

**共同规则**：

1. 每句话都要能回答“证据等级是什么、来源是谁”；
2. 拿不准的医学表述，**删掉**比含糊留着好；
3. 任何页面都不出现诊断、用药、剂量；
4. 急症红旗（胸痛、呼吸困难、意识改变）一律先写“立即就医”。

## 4. 每天 30 分钟的固定动作

**开工（10 分钟）**

```bash
git switch main
git pull
git switch -c feat/今天的任务
```

对 Cline 说：`读 AGENTS.md，复述今天的任务和 3 步计划，先不要改代码。`

**收工（20 分钟）**

```bash
npm run lint
npm run build
git add <改过的文件>
git commit -m "feat(范围): 一句话"
git push -u origin feat/今天的任务
```

然后开 PR → 对方 Approve → Squash and merge → 删分支。详细步骤见 14 §6。

## 6. 三分钟答辩脚本（照这个练）

**0:00–0:30 开场**

> 同一个器官，医生看到结构，系统生物学家看到关系，工程师看到信号。
> 我们做的不是把三种说法混在一起，而是给每一种说法标上**它有多可信**。

**0:30–1:30 演示（只演示一个器官）**

1. 打开 `/organ/heart`；
2. 点三镜标签：结构（四腔四瓣）、关系（自主神经）、信息（概念类比，明确标注）；
3. 指一个 **A 级**证据徽章：“这条来自解剖学教科书”；
4. 指一个 **C 级**：“这条是我们的叙事类比，不是医学结论”；
5. 打开误区区：“这条是常见误解，我们给了纠正和来源”。

**1:30–2:30 AI 策展人**

1. 问一个站内问题：“运动时心率为什么变快？”——回答带来源；
2. 问一个越界问题：“我胸痛怎么办？”——回答先建议就医，不给诊断；
3. 说一句：“模型不可用时，我们有预生成答案兜底，演示不会挂。”

**2:30–3:00 边界与收尾**

> 我们不提供诊断，不做治疗建议；中医内容标注为传统理论，信息论内容标注为概念类比。
> 所有图片只用 BodyParts3D 数据、原创图和 AIGC 辅助图，并记录生成来源。
> 下一版会做争议地图和信息负荷实验室。
