# 参赛材料核对清单（工作稿）

> 本清单依据 [2026 第九届 AI WEB 赛道页面](https://www.boxuegu.com/matchTrack/detail/?id=10037) 整理，供内部准备，不证明项目符合参赛要求。页面省赛时间表存在「11 月 18 日提交截止」与「作品指导后等待最终提交链接」的歧义；以赛事个人中心、最新通知和组委会确认为准。以下为待核对事项，不预填通过。
>
> 页面列明：仓库公开或授权评审、保留真实 Git 历史；视频 5–8 分钟、MP4、至少 1080p、普通话；技术文档 PDF 不超过 30 页，包含需求、架构、AI 选型与集成、创新、测试部署等；公网演示为可选加分项。允许 AI 辅助编程，选手须能清楚解释代码。

## 1. 参赛主体与协作

- [ ] 核实同校 1–3 人、指导教师不超过 2 人；西安交通大学本科生按页面规则核对 A 组或更高组别与实际报名信息。
- [ ] 核实两位学生实际完成、审阅和验证的工作；不将计划或他人工作写成学生已完成。
- [ ] 如实说明 Claude、Cline、DeepSeek、Claude Code 的实际使用方式，以及李小鹏的指导与实际贡献；按赛事规则确认是否允许、如何披露。
- [ ] 检查 Git 历史与协作说明一致；不伪造提交、不为改变外观改写已公开历史、不强制推送。

## 2. 仓库与文档

- [ ] 核对仓库地址、访问权限及评审期间可访问性。
- [ ] 逐项核对 README、技术文档、视频讲解稿和答辩口径与当前代码一致。
- [ ] 说明 AI 路径及来源 ID 校验的能力边界：结构校验不保证自然语言事实正确；兜底仍需浏览器能访问服务端。
- [ ] 核对全部医学表述、参考来源、证据分类、免责声明与实际审核记录；不要暗示未经确认的专业认证或临床验证。
- [ ] 中医内容注明传统理论，信息论说明是概念类比；不将其说成已证实的解剖机制或疗效。
- [ ] 核对代码、文字、三维模型及其他素材的来源、授权、署名及适用范围。
- [ ] 检查未提交密钥、`.env.local`、患者隐私或其他不应公开的内容；发现已泄露密钥应立即吊销更换，不能只从当前文件删除。
- [ ] 在项目根目录运行 `npm run lint` 和 `npm run build`，如实记录结果；检查 CI 状态。

## 3. 技术文档 PDF

- [ ] 按官方要求核对内容、文件格式、页数上限及提交方式。
- [ ] 从最终确认的 `TECH-DOC.md` 重新导出；检查页码、实际总页数、图表分页、字体和阅读效果。
- [ ] 文档更新后旧 PDF 可能过期，不用旧页数代替重新检查。

## 4. 视频与团队自查

- [ ] 核对官方要求的时长、分辨率、格式、字幕和提交方式；6 分 30 秒仅为本项目草稿目标。
- [ ] 两位同学按 `DEMO-VIDEO-SCRIPT.md` 分工排练，检查讲解与实际操作同步。
- [ ] 录制前实际测试三维、影响链、AI 与兜底流程；避免展示密钥或个人信息。
- [ ] 视频及材料中如实解释 AI 与指导参与，不将系统生物学等研究方向说成项目已完成临床验证或已证明疗效；常见问题稿供内部准备，省赛不以有现场答辩为前提。
- [ ] 使用的前沿论文和行业比较逐条核查来源、结论与适用范围；未核实的不要作为事实引用。

## 5. 部署与提交

- [ ] 确认实际部署地址、访问权限及稳定性；不要把建议部署平台写成已经上线。
- [ ] 如果演示 AI 上游异常，提前演练服务端可达条件下的兜底；断网不等于一定可以使用。
- [ ] 在官方渠道确认截止、提交内容、是否允许提交后更改、访问账号等要求。
- [ ] 提交前两位同学逐项复核，记录最终提交版本与时间；是否打 tag 由团队根据流程决定，不将其当成未经核实的赛事要求。
